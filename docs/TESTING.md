# 手で確かめること

`make test` は、画面に関係ない処理だけを確かめます。画面や macOS の許可に関わるため、手で確かめることをここに書きます。

## アップデート

- [ ] メニューバーのメニューに「アップデートを確認…」が出る（公開鍵の入ったビルド）。選ぶと、Dock にアイコンが出て、「アップデートを確認中…」の小窓が前面に出る。小窓は一瞬で閉じず、少なくとも 0.5 秒は出てから結果の画面に替わる。閉じると、Dock から消える
- [ ] 設定の「一般」→「Pinshot について」に、バージョンと「アップデートを確認…」・「新しい版を自動で確かめる」・最後に確かめた日時が出る
- [ ] 公開鍵の入っていないビルド（`project.yml` の `SUPublicEDKey` が空）では、メニューの項目が出ず、設定には版と「使えません」の説明だけが出る
- [ ] 入れ替えそのもの（と、許可が外れないこと）は、下の「更新を通しで試す」で確かめる

### 更新を通しで試す

リリースの前や、更新まわり（Sparkle の版・署名・証明書）を変えたときに、手元で実際に入れ替えて確かめます。いちばん確かめたいのは、配る版と同じ証明書（Pinshot Dev）で署名した版どうしなら、更新しても画面収録・アクセシビリティの許可が外れないことです。

ふだんの Pinshot とは別の ID（`dev.portfolio.pinshot.UpdateTest`）・別の名前（`PinshotUpdateTest`）・別のデータのフォルダ（`~/Library/Application Support/PinshotUpdateTest`）の試験用アプリを使うので、ふだんの Pinshot の許可・設定・履歴・浮かせた画像・Gyazo の許可証には触れません。更新ファイルの署名の鍵もその場で作るので、リリース用の鍵がなくても試せます。

1. `make stop` で、ふだんの Pinshot を終了する（ショートカットが重ならないように）
2. `make update-test` を流す。古い版と新しい版の試験用アプリを作り、新しい版を手元のサーバー（`http://localhost:8766`）から配り始める。2 つの版の「同じアプリ」の条件（`identifier "dev.portfolio.pinshot.UpdateTest" and certificate leaf = H"…"`）が同じであることも出る
   - ポートは、Pinshelf の試験（8765）とぶつからないよう 8766 にしている。ほかのものが使っていると、ビルドの前に止まって、何が使っているかの調べ方を出す。空いているポートで試すときは `make update-test UPDATE_TEST_PORT=8800` のように渡す
3. 画面に出る 2 通りのどちらかで、古い版を開く
   - **手早く試す**: 手元でビルドした古い版（`build/update-test/old/PinshotUpdateTest.app`）を、そのまま開く。更新まわりのコードを変えたときに。プロジェクトが「書類」などのフォルダの中にあると、入れ替えのときに macOS が「フォルダ内のファイルにアクセス」を確かめるので、許可する（入れ替えの部品が、そのフォルダの中のアプリを書き換えるため。配る版はアプリケーションフォルダに置くので、出ない）
   - **配る形に近づけて試す**: 古い版をブラウザでダウンロードし、アプリケーションフォルダに入れて、「このまま開く」で開く。ダウンロードの印（quarantine）が付いたままの版から更新できるかを確かめる。止められずに開いたときは、そのまま進めてよい（手元のサーバーからのダウンロードでは印が付かないことがあり、この Mac で一度開いた版は止められないこともある）。あとから `xattr -w` で印を付けると、別の場所に写して動かす扱い（App Translocation）になって更新できなくなるので、付けない。リリースの前と、Sparkle の版や署名を変えたときに
   - どちらで開いても、すぐに新しい版を確かめ、メニューバーのアイコンに小さな丸が付く（初めて開いたときか、前に確かめてから 1 時間以上たっているとき）。ここではまだ選ばない
4. 画面収録とアクセシビリティを許可する（初めて開くと出る使い方の窓から。システム設定の一覧には `PinshotUpdateTest` と出る）。画面収録をオンにして開き直すと、丸は消える（見つけた版は動いている間しか覚えておらず、次に自動で確かめるのは、前に確かめてから 1 時間後のため）。⌘⇧2 で 1 枚撮って浮かせたままにし、設定の「一般」で「ログイン時に起動」をオンにする
5. メニューの「アップデートを確認…」を選び（丸が残っていれば、メニューの上の「新しいバージョン … があります…」でもよい）、「アップデートをインストール」→「インストールして再起動」と進む

確かめること:

- [ ] 開いてすぐ、自動で新しい版を見つけて、画面を割り込ませずに、アイコンの丸とメニューで知らせる（手順 3。記録には `Found version …: showing the menu bar badge` と残る）
- [ ] 新しい版が開き直すときに、macOS の確認の画面（「開発元を確認できない」など）が出ない
- [ ] 設定の「一般」のバージョンが、新しい版になっている
- [ ] **画面収録・アクセシビリティの許可が外れていない**：メニューに「画面収録の許可が必要です…」が出ず、設定の「一般」で「許可済み」のまま。⌘⇧2 で、許可を聞かれずに撮れる（記録の「起動しました: …、画面収録: 許可済み、アクセシビリティ: 許可済み、…」でも確かめられる）
- [ ] 浮かせていた画像が戻っている。「ログイン時に起動」がオンのまま
- [ ] もう一度「アップデートを確認…」を選ぶと、「最新版を使用しています」と出る

終わったら:

1. 設定の「一般」で「ログイン時に起動」をオフに戻してから、試験用の Pinshot を終了する（戻し忘れたときは、システム設定 →「一般」→「ログイン項目」で外す）
2. アプリケーションフォルダに入れた `PinshotUpdateTest.app` は、ゴミ箱に入れる
3. サーバーを control + C で止める
4. 試験用アプリの許可を外す（システム設定 →「プライバシーとセキュリティ」の「画面収録」「アクセシビリティ」で `PinshotUpdateTest` を「−」で消す。ターミナルなら `tccutil reset ScreenCapture dev.portfolio.pinshot.UpdateTest` と `tccutil reset Accessibility dev.portfolio.pinshot.UpdateTest`）
5. 試験用のデータも消すときは、`~/Library/Application Support/PinshotUpdateTest` をゴミ箱に入れ、`defaults delete dev.portfolio.pinshot.UpdateTest` を流す（ふだんの Pinshot のデータ `~/Library/Application Support/Pinshot` と取り違えないように、フォルダの名前で確かめる）。作ったアプリは `build/update-test` にあり、`make clean` で消える

試験のあいだの macOS の記録は、`make update-test-log` で `build/update-test/system.log` に書き出せます（直近 30 分。`SINCE="2026-11-26 19:50:00"` のように、いつからかを渡せる）。Sparkle の入れ替えの部品の記録と、macOS の側（許可の確かめなど）が試験用アプリについて出した記録が入るので、許可が引き継がれたかの裏取りと、うまくいかないときの手がかりになります。アプリも、起動のたびに「版・画面収録とアクセシビリティの許可・『ログイン時に起動』」を記録に残すので、入れ替えの前と後を見比べられます。

比べるために、アドホック署名どうしの更新も試せます（`make update-test UPDATE_TEST_SIGN_IDENTITY=-`。ID と名前の後ろに `Adhoc` が付き、許可もデータも別になる）。こちらは、更新すると許可が外れるはずです。

証明書で署名した版どうしでも許可が引き継がれなかったときは、配る版の署名の方針を見直す（ARCHITECTURE.md の「署名」「更新」）。
